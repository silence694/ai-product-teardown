# 截图获取手册

拆解报告的质量上限由截图决定。这份文档解决一个问题：**怎么在 20 分钟内拿到 8-12 张真实的产品功能界面图。**

---

## 一、先建立判定标准

### 什么算「产品功能界面图」

图里必须能看见产品自身的**控件**，至少 2 类：

- 表单控件（输入框、下拉框、单选、开关、滑块）
- 数据展示（列表、表格列头、卡片、图表、状态标签）
- 导航结构（侧边栏、面包屑、页签、步骤条）
- 操作入口（按钮、悬浮工具条、右键菜单、拖拽手柄）

### 什么不算

| 类型 | 特征 | 为什么不算 |
|---|---|---|
| 营销插画 | 大色块、3D 小人、渐变光晕、无文字细节 | 是设计稿不是产品 |
| mockup / 线框图 | 有灰条占位、文字是 Lorem 或「标题文案」、控件边缘过于规整 | 是假图，会把报告拉到不可信 |
| 数据大屏 KV | 满屏炫光数字、无操作控件 | 是宣传物料 |
| 首页 hero 大图 | 只有 slogan + 一个 CTA 按钮 | 信息量约等于零 |
| 资讯配图 | 新闻站拍摄的发布会照、记者图 | 与产品功能无关 |
| 架构示意图 | 纯方块+箭头，没有 UI | 只能作为补充，不能当功能截图 |

**灰条 mockup 是最隐蔽的坑**：它看起来像界面，甚至能骗过白底检测算法。识别方法是放大看文字——真截图的文字是产品和数据（「订单编号」「2024-08-12」「李四」），mockup 的文字是通用占位（「标题」「内容」「输入文本」）或干脆是模糊的灰块。

## 二、五级来源的具体打法

### S 级 · 官方帮助中心 / 文档中心（首选，命中率最高）

操作手册是产品团队自己截的图，原生分辨率、无登录弹窗、无 cookie 横幅，是质量最好的来源。

**URL 规律**（按命中率排序）：

| 厂商 | 文档入口 | 找操作截图的路径 |
|---|---|---|
| 华为云 | `support.huaweicloud.com/<产品>0/` | `qs-<产品>0/`（快速入门，含建实例全流程）/ `usermanual-<产品>0/`（用户指南，功能最全） |
| 腾讯云 | `cloud.tencent.com/document/product/<数字ID>` | 产品页右上「文档」→「快速入门」/「操作指南」 |
| 阿里云 | `help.aliyun.com/zh/<产品>` | 「快速入门」章节，每步一张图 |
| 京东云 | `docs.jdcloud.com/cn/<产品>` | 「操作指南」 |
| 火山引擎 | `www.volcengine.com/docs/<数字>` | 「快速入门」 |
| 通用搜索式 | — | 搜「产品名 + 用户指南 site:support.*」 |

**关键技术点：用 `imgs` 模式提原图，不要截页面。**

文档页里的图是 `<img>` 元素指向 CDN 原图，尺寸通常 1200-2560px，比页面截图清晰一个量级，而且不带页面边框和侧栏导航。

```json
{ "name": "01_创建页", "url": "https://support.huaweicloud.com/usermanual-agentarts0/agentarts_05_0016.html",
  "mode": "imgs", "minW": 480, "minH": 250, "max": 8, "wait": 7000 }
```

参数经验值：`minW 480` / `minH 250` 能滤掉图标和装饰小图；`max` 设成需要数量的 1.5 倍（多抓几张留挑选余量）；`wait 7000` 给懒加载和 CDN 留时间。

### A 级 · 免登录可访问的产品界面

有没有登录墙，是这类来源能否使用的唯一标准。经验上以下几类通常不需要登录：

- **智能体 / 应用商店**：`yuanqi.tencent.com/agent-shop`、`coze.cn/store/agent`、各家「应用广场」「模板中心」
- **插件市场**：`yuanqi.tencent.com/plugin-shop`
- **Playground / 体验区**：大模型产品的「免费试用」入口
- **公开 Demo 链接**：发布会演示用的分享链接（有的带过期时间）

用 `page` 模式截，`deviceScaleFactor=2` 已内置，输出即 2 倍高清。

```json
{ "name": "02_智能体商店", "url": "https://yuanqi.tencent.com/agent-shop",
  "mode": "page", "wait": 6000, "fullPage": false }
```

**`fullPage` 建议设 false**：整页截图动辄 3000px 高，嵌进报告里细节全糊，读者看不到控件。默认只截首屏，需要更多信息就配 `selector` 截具体模块。

一个站能不能用，30 秒就能试出来：`page` 模式跑一次看产出——如果满屏扫码弹窗、或者红字提示「请先登录」，立刻放弃换来源，不要试图绕过登录墙。

### B 级 · 官网产品页功能模块（必须甄别）

**这是坑最深的一级。** 中国云厂商官网产品页约 **70%** 的「界面图」是设计稿 mockup——带占位灰条、文字模糊、控件比例失真。

实测数据：华为云 AgentArts 产品页抓下 8 张候选图，逐张目视后只有 2 张是真控制台，其余全是示意图。

用法：配 `selector` 只截特定功能模块区，比整页截图干净。

```json
{ "name": "03_功能模块", "url": "https://xxx.com/product/agent",
  "mode": "page", "selector": ".feature-section", "wait": 6000 }
```

抓到后用 `pick_ui.py` 打分，**分数高的也要多看两眼**——线框图白底率和边缘密度都很高，能拿到 80 分以上。

判断官网值不值得抓，有个快速信号：**页面里有没有 GIF / 视频演示**。有的产品会用录屏代替 mockup，那种页面里常能找到真实操作画面。

### C 级 · 应用商店截图

移动端产品（App、小程序）只有这条路走得通。

- App Store：页面底部「预览」区的图，分辨率 1290×2796，质量极好
- 国内安卓市场：华为应用市场、小米应用商店的商品详情页
- 微信小程序：小程序资料页的截图，或开发者社区文章里的实机图

`imgs` 模式可直接从 App Store 页面提原图，`minW` 可设到 700（App 截图本身就宽）。

### D 级 · 资讯 / 新闻配图（补位，≤2 张）

只在以下情况用：产品刚发布还没写文档、关键功能是线下首发、或某个新功能只有发布会截图。

必须遵守：
1. caption 里明确标注「**资讯配图**」，让读者知道这不是产品界面
2. 全篇不超过 2 张
3. 优先选**发布会现场演示的实拍**而不是记者拍的人像/会场照

**明确不要的站**（v1 报告踩过的坑）：`ce.cn`、`stdaily.com`、`mydrivers.com`、`100ec.cn`、各类「XX资讯」「XX观察」转载站。这些站的内容 99% 是通稿和会场照。

## 三、按产品类型找图（决策树）

```
产品是云厂商的 to B 平台？
├─ 是 → 直接去 support.<域名> / docs.<域名>，搜「快速入门」
│        └─ 找到后 imgs 模式，一次能出 6-10 张真控制台图  ← 最省力
└─ 否 ↓

产品是消费级 / 免登录的 AI 应用？
├─ 是 → 找「商店 / 广场 / 模板 / 体验区」页，page 模式截 3-5 张
│        └─ 若打开是登录墙 → 转去官方文档或应用商店
└─ 否 ↓

产品是移动端 App / 小程序？
├─ 是 → App Store / 安卓市场，imgs 模式
└─ 否 ↓

产品是 HR SaaS / 垂直 to B（北森、Moka、飞书 People）？
└─ 官网功能页多为 mockup
    → 优先级 1：help.<域名> / 帮助中心的图文教程
    → 优先级 2：B 站 / 视频号的官方产品演示录屏，逐帧截关键画面
    → 优先级 3：客户案例文章里的实机截图（常在客户官网或公众号）
```

## 四、失效模式清单

这些坑都真实踩过，遇到时不要在同一路径上反复重试。

| 现象 | 根因 | 处置 |
|---|---|---|
| `imgs` 模式抓出 0 张 | 图是懒加载，没滚动就提取 | 脚本已内置滚动；仍失败则加 `wait` 到 10000 |
| 抓到的全是 banner 和 logo | 尺寸阈值太低 | 提高 `minW` 到 560、`minH` 到 300 |
| 抓到的图是占位灰条 | 页面本身用 mockup | 换来源，别调参数 |
| 截图被扫码弹窗盖住 | 登录墙 | 脚本已自动清弹窗；清不掉就换来源 |
| 截出来是一整页长图、字看不清 | `fullPage: true` | 改 false，或配 `selector` 局部截 |
| SPA 站爬不到子页面链接 | 路由不写 `<a href>` | 手写 URL（腾讯元器、Kimi 等都是这种） |
| 图片能抓但下载 403 | CDN 有 referer 校验 | 加 `referer` 字段，或改用 `page` 模式截页面 |
| 文档页图片是 SVG 流程图 | 文档本身只有流程图没截图 | 翻同产品的其他章节，找「操作步骤」页 |

### 关于「文档页只有流程图」

很多国产 SaaS 的文档写得像 PPT——全是架构流程图，没有一张控制台截图。这类产品的 S 级来源实际不可用，直接跳到 A 级（找免登录界面）或 C 级（应用商店）。

判断方法：打开文档的「快速入门」，如果第一步到第五步之间没有任何 `<img>` 尺寸超过 480px，就换路子。

## 五、提效技巧

**1. 一次配置多个候选源，跑完再挑。**
不要一个 URL 跑一次。把 S/A/B 级来源全写进一个 config，一次跑完得到 20-30 张候选，再用 `pick_ui.py` 打分 + 目视，比逐个试快 3 倍。

**2. 截图命名即排序。**
`01_xxx.png` 的序号就是它在报告里出现的顺序。这样整理截图目录时就已经完成了内容编排，写 spec 时不用回头想「这张放哪」。

**3. caption 现场写，不要事后补。**
看图的那一刻写 caption 最准——「左栏四个必填项、右栏实时预览」这种细节，过 20 分钟就记不清了。文件名旁边可以先记一行备注。

**4. 官方架构图单独留一张。**
架构章节需要的图往往不在文档正文里，而在产品页的「产品架构」区块或技术博客里。这类图 `imgs` 模式抓不到（常是 SVG 或 Canvas），要用 `page` + `selector` 单独截。

**5. 图不够时的最后手段：官网演示视频。**
多数 to B 产品会在官网或 B 站放 2-3 分钟演示视频。用浏览器打开视频，拖到关键操作节点截图——虽然不如原生截图清晰，但**是真实操作界面**，比 mockup 和资讯图强得多。这类图在 caption 里标注「官方演示录屏截帧」。

## 六、核验（交付前必做）

对每张图问四个问题，答不上就换：

1. 这张图来自哪个 URL？（必须能在 `sources` 里指到）
2. 图里能看见几个产品控件？（<2 个 → 不算功能图）
3. 文字是产品真实内容还是占位符？（占位 → mockup）
4. 这张图说明了什么设计决策？（说不出来 → 这张图是装饰，删掉）

第 4 条最重要。一张说不清「为什么放它」的图，会让读者觉得报告在凑数。
